Chapter 01

Overview

Breakdown Planner is built on the Breakdown Structure — breaking a large piece of work down until each part is unambiguous, the standard project management approach (PMBOK). One project can carry several structures at once:

TypeFull nameWhat it is for
WBSWork Breakdown StructureTasks + schedule + cost — the heart of the app
OBSOrganizational Breakdown StructureWho or which unit is responsible for what
CBSCost Breakdown StructureWhich category a cost falls into, and the totals
RBSRisk Breakdown StructureRisk register: likelihood × impact
PBSProduct Breakdown StructureProducts and modules to deliver

Highlights: one tree editor for every structure (drag and drop, indent and outdent, automatic numbering 1 / 1.1 / 1.1.1) · FS/SS/FF/SF dependencies with automatic cycle protection · a Gantt that draws the critical path in red alongside slack · WBS→OBS/CBS links that roll up in reverse · undo/redo, JSON/CSV export, JSON import, and a Thai-English toggle on every screen

Best for

small to mid-sized projects, small teams and personal work, and learning WBS, Gantt and CPM through something concrete — for the limits worth knowing first, see chapter 10

Chapter 03

Concepts to know first

Leaf tasks are the source of truth

The most important rule — real data is entered on tasks with no children only. Every value on a parent is computed:

ValueLeaf taskParent (has children)
Start date / duration✏️ Entered🔒 Span of its children (min start - max end)
Progress %✏️ Entered🔒 Weighted by child duration
Status✏️ Chosen🔒 Derived from progress
Cost✏️ Entered🔒 Sum of all descendants

Edit a leaf once and every parent above it updates immediately — there is no refresh button

Numbering is computed live

1, 1.1 and 1.1.1 are derived from the node's actual position on every render, so the numbers stay correct wherever you drag a row — they were never stored in the first place

One tab, one structure

Add a structure with the + Add structure button at the end of the tab bar · double-click a tab to rename it · the × on the active tab deletes it (deleting a structure deletes every node inside it, behind a confirmation dialog)

Drag and drop

Grab the dotted handle in front of the name and drag:

  • drop on the upper part of the target row to place it before that row
  • drop on the lower part to place it after that row
  • drop on the middle of a row to place it to place it as a child of that row

A node cannot be dropped into its own subtree, so the tree can never loop back on itself

Chapter 05

Schedule, progress and cost

Click any row and the inspector on the right shows the fields for that structure type:

  • WBS leaf — start date, duration in days, a Milestone checkbox (a zero-day marker, drawn as ◆ on the Gantt), progress %, status (to do / in progress / done) and cost
  • WBS parent — read-only derived values with a status badge
  • OBS — owner · CBS — budget · RBS — likelihood (%), impact (low/medium/high) and response plan · PBS — version
  • Every node has notes for anything else
Tips

Table columns edit in place like a spreadsheet — click a cell and type

The status bar at the bottom warns how many tasks still lack a start date or duration, and shows how much storage is in use

Chapter 06

Dependencies

Add them from the inspector of a WBS leaf — click + Add dependency pick the predecessor, then set the type and lag (in days, negative allowed):

TypeNameMeaning
FSFinish-to-StartThe predecessor finishes before the successor can start — by far the most common
SSStart-to-StartBoth start together (+lag starts the successor that many days later)
FFFinish-to-FinishBoth finish together
SFStart-to-FinishThe predecessor starts before the successor can finish — rare

The rules are enforced automatically, each with its own message:

  • ❌ No self-links and no cycles — the whole subtree is checked before a link is accepted
  • ❌ No duplicate edges
  • ❌ Only schedulable leaves, and both ends must be in the same structure

Dependencies are the input to the CPM pass that draws the critical path in the next chapter

Chapter 07

Gantt chart and critical path

Switch with the 📊 button — the name pane on the left stays in sync with the tree, collapsed branches included. Zoom by day, week or month, and hover a bar for its dates and slack

The principle

Bar positions come from a forward pass over the dependency network, in which the start date you enter acts as a pin: where a constraint forces a later start, the constraint wins. Tasks with no dates leave an empty row, and the status bar says so

The scope of the critical path

CPM applies only to scheduling structures such as the WBS, because a critical path needs a network of durations and dependencies. OBS (organisation), CBS (cost), RBS (risk) and PBS (products) carry neither, so there is no network to analyse — and standard practice likewise runs CPM only over the activity network derived from the WBS. The other structures receive roll-ups through links instead (chapter 8)

Chapter 08

Cross-structure links

The heart of planning across structures — link from the inspector of a WBS node:

  • 🏢 Assign to org unit (assigns) — WBS → OBS: who does this work
  • 🪙 Charge to category (charges) — WBS → CBS: which budget this work draws on
  • 📦 Deliver to product (delivers) — WBS → PBS: which product or module this work delivers
  • 🛡️ Mitigate risk (mitigates) — WBS → RBS: which risk this work responds to

Each link button filters the picker down to the right structure, the same pair cannot be linked twice, and every link is undoable like any other action

On the receiving side (open an OBS/CBS/RBS/PBS tab and click a node) you get inbound mini-schedule: the WBS tasks pointing at it, each with a status dot, date range and progress, ordered by start date, eight at a time with the rest one click away. Click a "materials" category, for instance, and you see the piling and foundation tasks charged to it with their schedules — not just a total

Technique

You can link a parent node (a branch) and the app expands it across every task inside, without double-counting a child that is also linked directly

chapter 10

How far does this app really go?

✅ Works well for

  • Small to mid-sized projects (hundreds of tasks) with a single planner holding the plan
  • Work whose scope has to be argued: construction, software, events, campaigns, consulting, relocations
  • Teaching PM fundamentals — WBS, dependencies, CPM and cost roll-up in one place
  • Confidential data and offline environments — not a byte leaves the machine

⚠️ Limits worth knowing first

LimitationWhat it means in practice
No backend or accountsNo sharing and no real-time collaboration — the data stays on that machine and browser
Consecutive-day calendarWeekends and holidays count as working days, so real elapsed time runs longer than shown
No resource levelling or baselineOver-allocation is not prevented, and there is no plan-versus-actual comparison
Storage ~5 MBComfortable into the hundreds and low thousands of nodes; beyond that the status bar turns red
CSV is export-onlyCSV cannot be imported — only this app's own JSON
Five fixed structure typesThere is no UI yet for a custom structure type
In short

as a personal planning tool and a teaching aid it is complete and genuinely in control · as an enterprise suite with collaboration and resource management, it is not — and was never meant to be

How to read the critical path in sample 1

  1. Open the WBS tab and switch to the Gantt — the red bars are the critical path (slack ≤ 0)
  2. Follow the red chain: site survey → design → BOQ → permit → piling zone A → foundations → levels 1-3 → topping out → partitions → tiling → ceilings → lobby → commissioning → handover (273 days in total)
  3. Hover an indigo bar such as "Install the passenger lift" (48 days of slack) or "Landscaping" (37 days) — either can slip a long way without moving the handover date
  4. Compare that with "Painting throughout the building" (~8 days) — a near-critical branch that turns critical the moment it slips past eight days
  5. Change the duration of "Apply for the construction permit" from 30 to 45 days and watch the whole chain — and the handover date — move with it

Every sample is scheduled by the real CPM engine and has its statuses stamped against today's date, so whenever you open one, the tasks that should read done or in progress do

Chapter 12

FAQ

Do I lose my data when I close the browser?

No — every edit persists to localStorage. Clearing site data does erase it, though, which is why exporting JSON now and then is worth the habit

Why can't I edit a parent's start date?

By design — a parent is derived from its children. Edit the leaf and the parent follows

Why doesn't the Gantt bar match the start date I entered?

CPM takes the later of the two: your pinned date and the constraint from its dependencies. To make them agree, adjust the dependency or its lag

Can I use it on more than one machine?

Export JSON on machine A and import it on machine B — there is no automatic sync

Thai comes out garbled when I open the CSV?

The file already carries a UTF-8 BOM — in another editor, open it as UTF-8

Do OBS / CBS / RBS / PBS have a critical path?

Not in principle. The critical path method analyses a network of tasks that carry durations and dependencies, which is what the WBS provides as an activity network. OBS is an organisation chart, CBS aggregates money, and RBS and PBS hold no relationships in time — none of them offer a network to analyse, and standard practice (PMBOK) likewise confines CPM to the project schedule. So the Gantt and dependency features open on the WBS only; OBS, CBS, RBS and PBS instead receive roll-ups (task counts, total cost) through links

Why doesn't the cost in the S-curve match the CBS budget column?

They are different fields. The S-curve uses the cost of each individual WBS task spread across its schedule, while "budget" is an attribute you type on the CBS side. They do not sync, by design: per-task cost is the source of truth for the reports, and budget serves as the ceiling or target you compare against later

chapter 13

Reports: S-curve and resource loading

The workspace's third view (the 📈 button beside table and Gantt) — it draws on every structure at once: the WBS supplies schedule and cost, the CBS supplies cost categories, and the OBS supplies org units. It opens from any tab as long as the project has at least one schedulable structure

Cumulative cost (S-curve)

  • The heavy line is the total — cumulative cost across every scheduled task, each counted once
  • The coloured lines are CBS cost categories from charges links, so you can see when money flows into which category
  • The red dashed vertical is today · switch between weekly and monthly in the bar above · hover for the cumulative value of every line
Calculation rulesMeaning
Cost spreads evenlyA 100,000 baht task over 4 days is 25,000 a day
Milestones land on one dayThe whole amount falls on the start date (zero duration)
Tasks with no start dateExcluded from the curve, with a yellow note under the chart naming the value left out
Tasks charged to several categoriesEach category counts the full cost of that task, as the footnote says — the total line still counts it once
Tasks charged to nothingCollected into the grey "unassigned" line

Beyond four CBS categories, the fifth onwards fold into an "other" line so the chart stays readable

Resource loading (OBS × schedule)

A heatmap of task-days — how many days each org unit is committed:

  • One row per OBS unit, with parent rows rolling up the work of every unit beneath them
  • Darker means heavier load (against the table's own maximum), white means free · click a row to open that unit in the inspector
  • Hover a cell for the tasks consuming those days · the "unassigned" row is the task-days nobody owns yet
Finding the bottleneck

Which unit is under most pressure, and in which week? Which work still has no owner? This one screen answers both

The links that came with the reports

delivers (WBS→PBS) and mitigates (WBS→RBS) — how to use them is in chapter 8 Both reports count assigns and charges only; delivers and mitigates connect the product and risk views to the work instead — click a product in the PBS, for instance, and you get a mini-schedule of the tasks that deliver it
