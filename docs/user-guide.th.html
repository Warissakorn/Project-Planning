บทที่ 01

ภาพรวม

Breakdown Planner ยึดหลัก Breakdown Structure — การ "หัก" งานใหญ่ออกเป็นงานย่อยจนชัดเจน ตามแนวทางมาตรฐานของงานบริหารโปรเจ็ค (PMBOK) โปรเจ็คหนึ่งอันมีได้หลายโครงสร้างพร้อมกัน:

ประเภทชื่อเต็มใช้ทำอะไร
WBSWork Breakdown Structureแตกงาน + กำหนดการ + ต้นทุน — หัวใจของแอป
OBSOrganizational Breakdown Structureใคร / หน่วยงานใดรับผิดชอบงานไหน
CBSCost Breakdown Structureต้นทุนอยู่หมวดไหน รวมเท่าไร
RBSRisk Breakdown Structureทะเบียนความเสี่ยง: โอกาสเกิด × ผลกระทบ
PBSProduct Breakdown Structureผลผลิต / โมดูลที่ต้องส่งมอบ

จุดเด่น: tree editor ตัวเดียวใช้ได้ทุกโครงสร้าง (ลากวาง, เลื่อนระดับ, เลขลำดับอัตโนมัติ 1 / 1.1 / 1.1.1) · dependency FS/SS/FF/SF กันวงจรอัตโนมัติ · Gantt วาด critical path สีแดงพร้อม slack · เชื่อม WBS→OBS/CBS แล้ว roll-up ย้อนกลับได้ · Undo/Redo, Export JSON/CSV, Import JSON และสลับภาษาไทย–อังกฤษได้ทุกหน้าจอ

เหมาะกับ

โปรเจ็คขนาดเล็ก–กลาง, ทีมเล็ก/งานส่วนตัว, และการเรียนรู้ WBS–Gantt–CPM อย่างเป็นรูปธรรม — ส่วนกรอบที่ควรรู้ก่อนใช้จริง อ่านในบทที่ 10

บทที่ 02

เริ่มต้นใน 3 นาที

สร้างโปรเจ็คใหม่

  1. เปิดแอป — หน้าแรกคือรายการโปรเจ็คของคุณ
  2. พิมพ์ชื่อ เช่น โครงการต่ออาคารสำนักงาน → กด สร้างโปรเจ็คใหม่
  3. แอปพาเข้า Workspace พร้อมแท็บ WBS ที่มีรากโครงสร้างชื่อเดียวกับโปรเจ็ครออยู่ — กด เพิ่มรายการย่อย เริ่มแตกงานได้เลย

หรือลองจากตัวอย่างสำเร็จรูป

กดปุ่ม โหลดตัวอย่าง 5 โปรเจ็ค ในหน้าแรก จะได้โปรเจ็คครบ 5 สไตล์ พร้อมวันที่ ความคืบหน้า dependency และ critical path เรียบร้อย (รายละเอียดใน บทที่ 11) — กดซ้ำไม่เกิดตัวอย่างซ้อน เพราะ id ตายตัว

แก้ไขชื่องาน

ดับเบิลคลิกที่ชื่อในตารางเพื่อแก้ไข · Enter บันทึก · Esc ยกเลิก

บทที่ 03

แนวคิดหลักที่ต้องรู้ก่อน

งานปลายสุด (leaf) คือ source of truth

กฎที่สำคัญที่สุด — ข้อมูลจริงกรอกที่งานไม่มีลูกเท่านั้น ส่วนงานแม่ทุกค่าถูกคำนวณ:

ค่างานปลายสุดงานแม่ (มีลูก)
วันเริ่ม / ระยะเวลา✏️ กรอกเอง🔒 span ของลูก (min start – max end)
% ความคืบหน้า✏️ กรอกเอง🔒 เฉลี่ยถ่วงน้ำหนักตามระยะเวลาลูก
สถานะ✏️ เลือกเอง🔒 อนุพันธ์จาก progress
ต้นทุน✏️ กรอกเอง🔒 ผลรวมของลูกทุกระดับ

แก้ที่ปลายสุดครั้งเดียว งานแม่ทุกระดับอัปเดตทันที — ไม่มีปุ่ม refresh

เลขลำดับคำนวณสด

เลข 1, 1.1, 1.1.1 คำนวณจากตำแหน่งจริงในต้นไม้ทุกครั้งที่ render — ลากย้ายไปไหนเลขก็ถูกเสมอ เพราะไม่เคยถูกเก็บลงฐานข้อมูลตั้งแต่แรก

แท็บ = หนึ่งโครงสร้าง

เพิ่มโครงสร้างใหม่ด้วยปุ่ม + เพิ่มโครงสร้าง ปลายแถบแท็บ · ดับเบิลคลิกแท็บเพื่อเปลี่ยนชื่อ · ปุ่ม × บนแท็บที่เปิดอยู่คือลบ (ลบโครงสร้าง = ลบทุก node ภายใน มี dialog ยืนยัน)

บทที่ 05

กำหนดการ ความคืบหน้า และต้นทุน

คลิกแถวใดก็ได้ → แผง Inspector ด้านขวาแสดงรายละเอียดตามชนิดโครงสร้าง:

  • WBS leaf — วันเริ่ม, ระยะเวลา (วัน), checkbox Milestone (งานจุดสำคัญ 0 วัน แสดง ◆ ใน Gantt), % ความคืบหน้า, สถานะ (รอทำ / กำลังทำ / เสร็จสิ้น), ต้นทุน
  • WBS parent — ค่าอนุพันธ์แบบ read-only พร้อม badge สถานะ
  • OBS — ผู้รับผิดชอบ · CBS — งบประมาณ · RBS — โอกาสเกิด (%), ผลกระทบ (low/medium/high), แผนรับมือ · PBS — เวอร์ชัน
  • ทุก node มี โน้ต สำหรับรายละเอียดเพิ่ม
เคล็ดลับ

คอลัมน์ในตารางแก้ตรงจุดได้เหมือน Excel — คลิกเซลล์แล้วพิมพ์ทันที

แถบล่างสุดของจอ (StatusBar) เตือนจำนวนงานที่ยังไม่มีวันเริ่ม/ระยะเวลา และแสดงขนาดพื้นที่จัดเก็บที่ใช้

บทที่ 06

ความสัมพันธ์ระหว่างงาน (Dependencies)

เพิ่มได้ใน Inspector ของ leaf ใน WBS — กด + เพิ่มความสัมพันธ์ เลือกงานก่อนหน้า (predecessor) แล้วตั้งประเภท + lag (วัน, ติดลบได้):

ประเภทชื่อความหมาย
FSFinish-to-Startงานก่อนเสร็จแล้วงานหลังค่อยเริ่ม — พบบ่อยที่สุด
SSStart-to-Startเริ่มพร้อมกัน (+lag = เริ่มตามหลัง lag วัน)
FFFinish-to-Finishเสร็จพร้อมกัน
SFStart-to-Finishเริ่มงานก่อนแล้วงานหลังถึงเสร็จ — พบน้อย

ระบบบังคับกฎให้อัตโนมัติ พร้อมข้อความเตือนภาษาไทย:

  • ❌ ห้ามวนกลับตัวเองหรือสร้าง cycle — ตรวจทั้ง subtree ก่อนยอมรับ
  • ❌ ห้าม edge ซ้ำเดิม
  • ❌ เลือกได้เฉพาะ leaf ที่กำหนดการได้ และต้องอยู่โครงสร้างเดียวกัน

Dependency คือ input ของ CPM ที่ใช้วาด critical path ในบทถัดไป

บทที่ 07

Gantt Chart และ Critical Path

สลับมุมมองด้วยปุ่ม 📊 — แถวชื่อฝั่งซ้าย sync กับต้นไม้ทุกแถว รวม branch ที่พับอยู่: zoom รายวัน / รายสัปดาห์ / รายเดือน และ hover bar เพื่อดูลงวันที่ + slack

หลักการสำคัญ

ตำแหน่ง bar มาจาก forward pass ของ network (dependency) โดย "วันเริ่ม" ที่กรอก ทำหน้าที่เป็น pin — ถ้า constraint บังคับให้เริ่มช้ากว่า pin ระบบใช้วัน constraint งานที่ยังไม่ใส่วันที่จะเป็นแถวว่าง (StatusBar จะเตือน)

บทที่ 08

เชื่อมโยงข้ามโครงสร้าง (Links)

หัวใจของการวางแผนหลายโครงสร้าง — เชื่อมจาก Inspector ของ node ใน WBS:

  • 🏢 มอบหมายให้หน่วยงาน (assigns) — WBS → OBS: งานนี้ใครทำ
  • 🪙 ผูกต้นทุนกับหมวด (charges) — WBS → CBS: เงินงานนี้เข้าหมวดไหน

ฝั่งรับ (เปิดแท็บ OBS/CBS แล้วคลิก node) จะเห็น inbound links แบบ roll-up สด: "n งานที่เชื่อมโยง" และ "ต้นทุนรวม x" — เช่น คลิกหมวด "ค่าวัสดุ" แล้วเห็นว่างานเสาเข็มและฐานราก ผูกเข้ามารวมกันเท่าไร

บทที่ 09

Undo, Export และ Import

ฟีเจอร์วิธีใช้
Undo / Redo Ctrl+Z / Ctrl+Shift+Z หรือ Ctrl+Y — stack ลึก 50 ชั้น ครอบคลุมทุก action
Export JSONHeader → ส่งออก → Export JSON — backup ทั้งโปรเจ็ค มี schemaVersion สำหรับ migration
Export CSVHeader → ส่งออก → Export CSV — เฉพาะแท็บที่เปิด, มี BOM UTF-8 (Excel อ่านไทยถูก), มีคอลัมน์ Code / Level / ค่า roll-up
Import JSONหน้าแรก → นำเข้า JSON — validate 3 กรณี: JSON พัง / ไม่ใช่ไฟล์แอปนี้ / เวอร์ชันใหม่กว่า — แจ้ง error เป็นภาษาไทย

Import โปรเจ็คที่ id ชนกับของเดิม → ระบบตั้ง id ใหม่ให้เอง สองโปรเจ็คอยู่ร่วมกันได้

สำคัญ

ข้อมูลทั้งหมดอยู่ใน localStorage ของ browser เครื่องนี้เท่านั้น — ล้าง site data หรือสลับ browser คือข้อมูลไม่ติดไปด้วย Export JSON เก็บไว้เป็นระยะคือ backup ที่ดีที่สุด

บทที่ 10

แอปนี้ควบคุมงานได้จริงแค่ไหน?

✅ ใช้ได้ดีกับ

  • โปรเจ็คเล็ก–กลาง (หลักร้อย tasks) ที่ planner คนเดียวดูแลแผน
  • งานที่ต้องพิสูจน์ scope: ก่อสร้าง, software, event, campaign, ที่ปรึกษา, ย้ายที่ทำการ
  • การสอน PM fundamentals — WBS, dependency, CPM, cost roll-up ในที่เดียว
  • ข้อมูล confidential / สภาพแวดล้อม offline — ไม่มี byte ไหนออก internet

⚠️ กรอบที่ควรรู้ก่อนใช้

ข้อจำกัดผลต่อการใช้งาน
ไม่มี backend / accountไม่มี sharing หรือ collab real-time — ข้อมูลอยู่เฉพาะเครื่อง + browser นั้น
Calendar แบบ consecutive daysเสาร์–อาทิตย์ / วันหยุดนับเป็นวันทำงาน — ระยะเวลาจริงยาวกว่าที่เห็น
ไม่มี resource leveling / baselineกัน over-allocation ไม่ได้, เทียบ plan vs actual ยังไม่มี
Storage ~5 MBพอหลักร้อย–พัน nodes; เกินแล้ว StatusBar เตือนสีแดง
CSV เฉพาะ exportยัง import CSV ไม่ได้ — import ได้เฉพาะ JSON ของแอป
Type preset ตายตัว 5 แบบUI สร้าง custom structure type ยังไม่เปิด
สรุป

ในฐานะเครื่องมือวางแผนส่วนบุคคลและสื่อการสอน — ครบเครื่องและควบคุมได้จริง· ในฐานะ enterprise suite ที่ต้อง collab + resource management — ยังไม่ใช่ และไม่ได้ตั้งใจจะเป็น

บทที่ 11

5 โปรเจ็คตัวอย่างเพื่อการเรียนรู้

กด โหลดตัวอย่าง 5 โปรเจ็ค ในหน้าแรก — แต่ละอันสอน feature ต่างกัน:

#ตัวอย่างสอนอะไรStructures
1 ก่อสร้างอาคารสำนักงาน Full showcase: FS chain ยาว, SS+lag, milestone, critical path จริง, assigns + charges, ทะเบียนความเสี่ยง WBS + OBS + CBS + RBS
2 พัฒนาแอป FoodieGo Parallel branches (design ∥ dev) มาบรรจบ, milestone launch, PBS แยกผลผลิตเป็นโมดูล+เวอร์ชัน WBS + PBS + OBS
3 จัดสัมมนา Digital Transformation Timeline กระชับกำลังรันจริง — งานผ่านแล้ว done, ช่วงวันนี้ in_progress; งานที่มี predecessor หลายตัว WBS + OBS + CBS
4 แคมเปญเปิดตัว AIRA X1 ใช้ RBS จริงจัง (โอกาส×ผลกระทบ + แผนรับมือ), งบแคมเปญแบบ CBS WBS + CBS + RBS
5 ย้ายสำนักงาน Minimalism — WBS อย่างเดียวก็วางแผนได้ครบ เหมาะเริ่มจากศูนย์ WBS

ทุกตัวอย่างคำนวณวันที่ด้วย CPM engine ตัวจริงและตั้งสถานะตามวันที่เทียบ "วันนี้" — เปิดวันไหน งานที่ควร done / in_progress จะถูกต้องตามเวลาจริงเสมอ

บทที่ 12

คำถามที่พบบ่อย

ข้อมูลหายไหมถ้าปิดเบราว์เซอร์?

ไม่หาย — persist ลง localStorage ทุกครั้งที่แก้ แต่ถ้าล้าง site data จะหายจริง จึงควร export JSON เป็นระยะ

ทำไมแก้วันเริ่มของงานแม่ไม่ได้?

By design — งานแม่ derive จากลูก แก้ที่ leaf แล้วงานแม่ขยับเอง

ทำไม bar ใน Gantt ไม่ตรงกับวันเริ่มที่กรอก?

CPM เลือกวันที่ช้ากว่าระหว่าง pin ที่กรอก กับ constraint จาก dependency — อยากให้ตรงก็ปรับ dependency/lag ให้สอดคล้องกับวันที่

ใช้หลายเครื่องได้ไหม?
