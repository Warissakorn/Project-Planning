## 1. ภาพรวม

Breakdown Planner คือเครื่องมือวางแผนโปรเจ็คที่ยึดหลัก **Breakdown Structure** —
การ "หัก" งานใหญ่ออกเป็นงานย่อยจนชัดเจน ซึ่งเป็นวิธีมาตรฐานของงานบริหารโปรเจ็ค
(PMBOK) โดยแอปรองรับโครงสร้าง 5 ประเภทในโปรเจ็คเดียวกัน:

| ประเภท | ชื่อเต็ม | ใช้ทำอะไร |
|---|---|---|
| **WBS** | Work Breakdown Structure | แตกงานออกเป็นงานย่อย + กำหนดการ + ต้นทุน |
| **OBS** | Organizational Breakdown Structure | ใคร/หน่วยงานใดรับผิดชอบงานไหน |
| **CBS** | Cost Breakdown Structure | ต้นทุนอยู่ในหมวดไหน รวมเป็นเท่าไร |
| **RBS** | Risk Breakdown Structure | ทะเบียนความเสี่ยง: โอกาสเกิด × ผลกระทบ |
| **PBS** | Product Breakdown Structure | ผลผลิต/โมดูลที่ต้องส่งมอบ เวอร์ชันไหน |

**จุดเด่น**

- 🌳 Tree editor ตัวเดียวใช้ได้กับทุกโครงสร้าง — ลากวาง เลื่อนระดับ เลขลำดับอัตโนมัติ (1, 1.1, 1.1.1)
- 📅 ใส่วันเริ่ม + ระยะเวลาเฉพาะงานปลายสุด งานแม่**คำนวณให้เอง** (span, % รวมถ่วงน้ำหนัก, ต้นทุนรวม)
- 🔗 ผูก dependency FS/SS/FF/SF + lag พร้อมกันวงจร (cycle) อัตโนมัติ
- 📊 Gantt วาด Critical Path สีแดง + slack + today marker + zoom รายวัน/สัปดาห์/เดือน
- ↔️ เชื่อม WBS↔OBS (มอบหมายงาน), WBS→CBS (ผูกต้นทุน) แล้วดูยอดรวมย้อนกลับ
- 🌐 สลับภาษาไทย/อังกฤษได้ทุกหน้าจอ · Undo/Redo · Export JSON/CSV · Import JSON
- 💾 ข้อมูลเก็บใน localStorage ของเบราว์เซอร์ — **ไม่มี server ไม่มี login ไม่ส่งข้อมูลออกไปไหน**

เหมาะกับ: การวางแผนโปรเจ็คขนาดเล็ก–กลาง, งานส่วนตัว/ทีมเล็ก, และการเรียนรู้แนวคิด
WBS/Gantt/CPM อย่างเป็นรูปธรรม

## 2. เริ่มต้นใน 3 นาที

### สร้างโปรเจ็คใหม่

1. เปิดแอป → หน้าแรกคือรายการโปรเจ็ค
2. พิมพ์ชื่อโปรเจ็คในช่อง เช่น `โครงการต่ออาคารสำนักงาน` → กด **สร้างโปรเจ็คใหม่**
3. แอปจะพาเข้า Workspace พร้อมแท็บ WBS ที่มีรากโครงสร้างชื่อเดียวกับโปรเจ็ครออยู่

### ลองกับโปรเจ็คตัวอย่าง (แนะนำสำหรับผู้เริ่ม)

กดปุ่ม **💡 โหลดตัวอย่าง 5 โปรเจ็ค** ในหน้าแรก — จะได้โปรเจ็คครบ 5 สไตล์
(ก่อสร้าง / แอปมือถือ / สัมมนา / แคมเปญการตลาด / ย้ายสำนักงาน) พร้อมข้อมูล
วันที่ ความคืบหน้า dependency และ critical path เรียบร้อย กดปุ่มซ้ำไม่ซ้ำเพราะ id ตายตัว

### เพิ่มงานแรกของคุณ

- กด **เพิ่มรายการย่อย** (Add child) — เพิ่มงานลงใต้แถวที่เลือกอยู่ (ไม่เลือก = เพิ่มเป็นแถวบนสุด)
- ดับเบิลคลิกชื่อเพื่อแก้ไข, Enter = บันทึก, Esc = ยกเลิก

## 3. แนวคิดหลักที่ต้องรู้ก่อน

### งานปลายสุด (Leaf) คือ source of truth

กฎที่สำคัญที่สุดของแอปนี้:

| | งานปลายสุด (ไม่มีงานลูก) | งานแม่ (มีงานลูก) |
|---|---|---|
| วันเริ่ม / ระยะเวลา | ✏️ กรอกเองได้ | 🔒 คำนวณจากลูก (min start – max end) |
| % ความคืบหน้า | ✏️ กรอกเอง | 🔒 เฉลี่ยถ่วงน้ำหนักตามระยะเวลาลูก |
| สถานะ | ✏️ เลือกเอง | 🔒 อนุพันธ์จาก progress |
| ต้นทุน | ✏️ กรอกเอง | 🔒 ผลรวมของลูกทุกระดับ |

พอแก้ข้อมูลที่ปลายสุด ทุกค่าของงานแม่ทุกระดับจะอัปเดตทันที — ไม่มีปุ่ม refresh

### เลขลำดับคำนวณสด ไม่เก็บในฐานข้อมูล

เลข 1, 1.1, 1.1.1 คำนวณจากตำแหน่งจริงในต้นไม้ทุกครั้งที่ render — ลากย้ายไปไหน
เลขก็ถูกต้องเสมอ ไม่มีวันเพี้ยน

### แท็บ = หนึ่งโครงสร้าง

โปรเจ็คหนึ่งอันมีได้หลาย structure instance (เช่น WBS หนึ่งอัน + CBS สองอันสำหรับ
งบสองปี) เพิ่มได้จากปุ่ม **+ เพิ่มโครงสร้าง** ด้านขวาของแถบแท็บ, เปลี่ยนชื่อแท็บด้วย
ดับเบิลคลิก, ลบด้วยปุ่ม × บนแท็บที่ active (ลบโครงสร้าง = ลบทุก node ในนั้น)

## 4. สร้างและจัดโครงสร้างงาน

### Toolbar เหนือตาราง

| ปุ่ม | ทำอะไร |
|---|---|
| ➕ เพิ่มรายการย่อย | เพิ่ม node ลูกใต้แถวที่เลือก (ไม่เลือก = ลงใต้ราก) |
| เพิ่มรายการข้างเคียง | เพิ่ม node ระดับเดียวกัน ถัดจากแถวที่เลือก |
| ⇥ / ⇤ (Indent/Outdent) | เลื่อนระดับซ้าย–ขวา |
| พับ / กางทั้งหมด | collapse/expand ทุก branch |
| 🗑 ลบ | ลบแถวที่เลือก + ลูกทั้งหมด (มี dialog ยืนยัน) |
| 📋 / 📊 toggle | สลับมุมมอง ตาราง ↔ Gantt (เฉพาะโครงสร้างที่มี scheduling เช่น WBS) |

### ลากวาง (drag & drop)

จับที่ **handle รูปจุด 6 จุด** ด้านหน้าชื่อ แล้วลาก:

- ปล่อยบน **ส่วนบน (30% แรก)** ของแถวเป้าหมาย = วาง *ก่อน* แถวนั้น
- ปล่อยบน **ส่วนล่าง (30% ท้าย)** = วาง *หลัง* แถวนั้น
- ปล่อยบน **กลางแถว** = วาง *ใน* เป็นลูกของแถวนั้น

แอปจะไม่ให้ลาก node ไปใส่ใน subtree ของตัวเอง (กัน tree วนกลับตัว)

### ใช้คีย์บอร์ดนำทาง

| ปุ่ม | ผล |
|---|---|
| ↑ / ↓ | เลื่อน selection ขึ้น–ลง (Home / End = ตัวแรก/ตัวสุดท้าย) |
| → | กาง branch ที่พับอยู่ / ลงไปหาลูกตัวแรก |
| ← | พับ branch / ขึ้นไปหางานแม่ |
| Ctrl+Z / Ctrl+Y | Undo / Redo (ทุก action รวมถึงการลากวาง) |

แถวที่เลือก scroll ตามอัตโนมัติ

## 5. กำหนดการ ความคืบหน้า และต้นทุน

คลิกแถวใดก็ได้ → แผง **Inspector** ด้านขวาจะแสดงรายละเอียด:

- **ชื่อ / โน้ต** — แก้ได้ทุก node
- **WBS leaf**: วันเริ่ม (date picker), ระยะเวลา (วัน), checkbox **Milestone**
  (งานจุดสำคัญที่ใช้เวลา 0 วัน แสดงเป็นสี่เหลี่ยมข้าวหลามตัด ◆ ใน Gantt),
  % ความคืบหน้า, สถานะ (รอทำ / กำลังทำ / เสร็จสิ้น), ต้นทุน
- **WBS parent**: แสดงค่าอนุพันธ์เป็น read-only พร้อม badge สถานะ
- **OBS**: ฟิลด์ผู้รับผิดชอบ · **CBS**: งบประมาณ · **RBS**: โอกาสเกิด(%), ผลกระทบ(low/medium/high), แผนรับมือ · **PBS**: เวอร์ชัน

> 💡 **เคล็ดลับ:** คอลัมน์ในตารางแก้ไขได้ตรง ๆ เหมือน Excel — คลิกเซลล์แล้วพิมพ์ได้เลย

แถบด้านล่างสุด (StatusBar) จะเตือนจำนวนงานที่**ยังไม่มีวันเริ่ม/ระยะเวลา**
และขนาดพื้นที่จัดเก็บที่ใช้อยู่

## 6. ความสัมพันธ์ระหว่างงาน (Dependencies)

เพิ่มได้ใน Inspector เฉพาะ **leaf ของ WBS** กด **+ เพิ่มความสัมพันธ์** → เลือกงานก่อนหน้า
(predecessor) → ตั้งประเภท + lag (วัน, ติดลบได้):

| ประเภท | ชื่อ | ความหมาย |
|---|---|---|
| **FS** | Finish-to-Start | งานก่อน**เสร็จ**แล้วงานหลังค่อย**เริ่ม** (พบบ่อยสุด) |
| **SS** | Start-to-Start | เริ่มพร้อมกัน (+lag = เริ่มหลังกัน lag วัน) |
| **FF** | Finish-to-Finish | เสร็จพร้อมกัน |
| **SF** | Start-to-Finish | เริ่มงานก่อนแล้วงานหลังถึงเสร็จ (หาพบน้อยสุด) |

**กฎที่ระบบบังคับให้อัตโนมัติ** (มีข้อความเตือนเป็นภาษาไทยเมื่อขัด):

- ❌ ห้ามวนกลับตัวเอง / สร้าง cycle — ระบบตรวจทั้ง subtree ก่อนยอมรับ
- ❌ ห้ามซ้ำ edge เดิม
- ❌ เลือกได้เฉพาะ leaf ที่กำหนดการได้ และอยู่**โครงสร้างเดียวกัน** (WBS กับ WBS)

Dependency คือสิ่งที่ CPM ใช้คำนวณ Critical Path ในข้อ 7

## 7. Gantt Chart และ Critical Path

สลับมุมมองด้วยปุ่ม 📊 ที่ toolbar (เฉพาะแท็บที่มี scheduling) — แถวซ้าย sync กับ
ต้นไม้ทุกแถว รวม branch ที่พับอยู่:

- **Zoom**: รายวัน (26px/วัน) / รายสัปดาห์ / รายเดือน
- **Today marker**: เส้นแดงแนวตั้ง = วันนี้
- **Bar**: แสดงช่วง es–ef ที่ CPM คำนวณ; hover เพื่อดูวันที่จริง + slack (วัน)
- **Critical path**: bar สีแดง = งานที่ slack ≤ 0 — งานสายแม้วันเดียวแล้วโครงการเลยแผน
- **Milestone**: ◆ สีเหลือง

**หลักการสำคัญ:** ตำแหน่ง bar = forward pass จาก network (dependency ที่คุณสร้าง)
โดย "วันเริ่ม" ที่คุณกรอกทำหน้าที่เป็น pin — ถ้า constraint บังคับให้เริ่มช้ากว่า pin
ระบบจะใช้วันที่ constraint (bar เลื่อนขวา) ดังนั้น Gantt กับตารางจะสอดคล้องกันเมื่อ
วันที่ที่กรอกไม้ขัดกับ dependency

งานที่ยังไม่ใส่วันที่จะเป็นแถวว่างใน Gantt — StatusBar จะเตือนให้

## 8. เชื่อมโยงข้ามโครงสร้าง (Links)

หัวใจของ multi-structure planning — เชื่อมจาก Inspector ของ node ใน WBS:

- **🏢 มอบหมายให้หน่วยงาน (assigns)** — WBS → OBS: งานนี้ใครทำ
- **🪙 ผูกต้นทุนกับหมวด (charges)** — WBS → CBS: เงินงานนี้จ่ายเข้าหมวดไหน

ฝั่งตรงข้าม (เปิดแท็บ OBS/CBS แล้วคลิก node) จะเห็น **inbound links**:
"มี n งานที่เชื่อมโยง" และ "ต้นทุนรวม x" — คือ roll-up ย้อนกลับแบบ real-time
(เช่น คลิกหมวด "ค่าวัสดุ" เห็นว่างานเสาเข็ม+ฐานราก ผูกมาแล้วรวม 830,000)

## 9. Undo, Export และ Import

| ฟีเจอร์ | วิธีใช้ |
|---|---|
| Undo / Redo | Ctrl+Z / Ctrl+Shift+Z (หรือ Ctrl+Y) หรือปุ่มใน header — stack ลึก 50 ชั้น |
| Export JSON | Header → **ส่งออก → Export JSON** — backup ทั้งโปรเจ็ค (มี schemaVersion) |
| Export CSV | Header → **ส่งออก → Export CSV** — export เฉพาะแท็บที่เปิดอยู่, มี BOM UTF-8 เปิดใน Excel ภาษาไทยไม่เพี้ยน, มีคอลัมน์ Code/Level/rollup |
| Import JSON | หน้าแรก → **นำเข้า JSON** — validate ก่อน: JSON พัง / ไม่ใช่ไฟล์แอปนี้ / สร้างจากเวอร์ชันใหม่กว่า จะแจ้ง error เป็นภาษาไทย |

Import โปรเจ็คที่มี id ซ้ำกับที่มีอยู่ → ระบบตั้ง id ใหม่ให้เอง ทั้งสองอันอยู่ร่วมกันได้

> ⚠️ ข้อมูลทั้งหมดอยู่ใน localStorage ของเบราว์เซอร์เครื่องนี้เท่านั้น — ล้าง cache /
> สลับเบราว์เซอร์ = ข้อมูลหาย จึงควร Export JSON เป็น backup เป็นระยะ

## 10. แอปนี้ควบคุมงานได้จริงแค่ไหน?

**✅ ใช้ได้ดีกับ:**

- โปรเจ็คขนาดเล็ก–กลาง (หลักร้อย tasks) ที่ PLANNER คนเดียวดูแลแผน
- งานที่ต้องพิสูจน์ scope: ก่อสร้าง, software, event, campaign, ที่ปรึกษา, ย้ายที่ทำการ
- การสอน/เรียน PM fundamentals — WBS, dependency, CPM, cost roll-up ในที่เดียว
- สภาพแวดล้อม offline/confidential (ไม่มีข้อมูลออก internet เลย)

**⚠️ ยังไม่เหมาะกับ (รู้ก่อนใช้):**

| ข้อจำกัด | ผลต่อการใช้งาน |
|---|---|
| ไม่มี backend/account | ไม่มี sharing/collab แบบ real-time, ข้อมูลอยู่เฉพาะเครื่อง+browser นั้น |
| Calendar แบบ consecutive days | เสาร์–อาทิตย์/วันหยุดนับเป็นวันทำงาน — ระยะเวลาจริงจะยาวกว่าที่เห็น |
| ไม่มี resource leveling/baseline | จัดคนไม่ over-allocate ให้ไม่ได้, เทียบ plan vs actual ยังไม่มี |
| Storage ~5MB | พอหลักร้อย–พัน nodes; เกินแล้ว StatusBar เตือนสีแดง |
| CSV เฉพาะ export | ยัง import CSV ไม่ได้ (import ได้เฉพาะ JSON ของแอป) |
| Type preset ตายตัว | สร้าง structure type custom จาก UI ยังไม่เปิด (ใช้ 5 preset) |

**สรุป:** ในฐานะเครื่องมือวางแผนส่วนบุคคล/สอนงาน — ครบเครื่องและควบคุมได้จริง
ในฐานะ enterprise PM suite ที่ต้อง collab/resource management — ยังไม่ใช่ และไม่ได้ตั้งใจจะเป็น

## 12. คำถามที่พบบ่อย

**Q: ข้อมูลหายไหนถ้าปิดเบราว์เซอร์?**
ไม่หาย — persist ลง localStorage ทันทีที่แก้ทุกครั้ง แต่ถ้าล้าง site data จะหาย จึงแนะนำ export JSON เป็นระยะ

**Q: ทำไมแก้วันเริ่มของงานแม่ไม่ได้?**
By design — งานแม่ derive จากลูก แก้ที่ leaf แล้วแม่จะขยับเอง

**Q: ทำไม bar ใน Gantt ไม่ตรงกับวันเริ่มที่กรอก?**
CPM เลือกวันที่ช้ากว่าระหว่าง "pin ที่กรอก" กับ "constraint จาก dependency" —
ถ้าอยากให้ตรง แก้ dependency/lag ให้สอดคล้องกับวันที่

**Q: ใช้กับหลายเครื่องได้ไหม?**
Export JSON จากเครื่อง A → Import ที่เครื่อง B (ข้อมูลไม่ sync อัตโนมัติ)

**Q: เปิด CSV แล้วภาษาไทยเพี้ยน?**
ไฟล์มี BOM แล้ว — ถ้าเปิดด้วย editor อื่น ให้เลือก encoding UTF-8
